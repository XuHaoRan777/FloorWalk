# Web 控制台剩余页面布局整理

> ID：`FW-042`
>
> 状态：`approved`

## 目标

按 FW-041 确定的 Web 设计基线，整理今日视图、审核队列、审核详情、门店、账号、通知收件箱和我的页面布局。
只改 `apps/web` 的页面呈现，保留现有业务逻辑、路由、数据获取与接口。
验收方式为 A。

## 非目标

- 不修改 `packages/tokens/tokens.css` 的变量或取值。
- 不修改公共组件外观、导航或页面框架；仅使用现有样式、语义色和组件。
- 不改变业务逻辑、路由、数据获取、API 契约、权限、认证、数据用途或部署拓扑。
- 不修改 Mobile 页面，不新增依赖。
- Web 视口不覆盖小于 `768px`。

## 确认的布局表

| 页面 | 进来第一眼看到什么 | 主要操作 | 次要信息怎么放 | 窄屏（768 / 1024）怎么变 |
| --- | --- | --- | --- | --- |
| 今日视图 | 标题与日期、今日指标、各店任务表 | 刷新；从警告或待处理项查看任务 | 警告与待人工列表置于任务主表之后，空态保留 | 指标两列；操作可换行；任务表仅在自身区域横向滚动 |
| 审核队列 | 标题、刷新操作、待人工任务列表 | 刷新队列、打开任务 | 今日已判定列表置于待人工之后；状态同时显示文字和语义色 | 任务行分层，理由与状态可换行；不产生页面级横向滚动 |
| 审核详情（含聊天） | 门店、日期、模板、判定状态与分数 | 返回队列、刷新、逐项判定 | 1440 下检查项主区与只读聊天并排；标题和任务摘要在上，状态用文字与语义色 | 1024、768 改为上下排列；长文本可换行，无页面级横向滚动 |
| 门店 | 标题与新增门店表单、门店表 | 新建、改名、启用或停用、刷新 | 店长与状态信息保留在对应数据行 | 表单收为窄列布局；门店表仅自身区域横向滚动 |
| 账号 | 标题与创建店长表单、账号表 | 创建、编辑、重置密码、启用或停用、刷新 | 角色、门店和状态保留在对应数据行 | 表单收窄并允许操作换行；账号表自身横向滚动，首列固定 |
| 通知收件箱 | 右侧收件箱、未读提示与最近通知 | 全部已读、选择通知跳转 | 时间、正文和已读状态随通知项排列 | 保持 Sheet 并限制在视窗内；通知正文换行 |
| 我的 | 标题、个人资料和昵称编辑 | 更新昵称或头像、修改密码、退出 | 登录名、角色等只读资料放在表单之后 | 资料表单单列，长登录名换行；不产生页面级横向滚动 |

## 验收标准

- AC-01（`建议采纳`）：今日视图按确认表组织标题、日期、指标、警告、待处理列表和任务表。768、1024、1440 宽度下，指标在窄屏双列，刷新及查看任务操作可用，任务表只在自身区域横向滚动。
- AC-02（`建议采纳`）：审核队列按确认表组织待人工和今日已判定任务。任务行在窄屏分层并允许理由换行；任务状态以文字和语义色同时表达；空列表仍有明确空态。
- AC-03（`建议采纳`）：审核详情按确认表呈现任务标题、摘要和现有审核操作。1440 宽度下检查项与只读聊天并排，1024、768 宽度下上下排列；0、1、很多检查项和聊天消息均可阅读，现有逐项判定动作不变。
- AC-04（`建议采纳`）：门店页按确认表把新增表单放在门店表之前，保留现有门店和店长信息；门店表仅在自身区域横向滚动，空列表仍可操作。
- AC-05（`建议采纳`）：账号页按确认表把创建表单放在账号表之前，保留角色、门店、状态和账号操作；窄屏账号表仅在自身区域横向滚动且首列固定，表单与操作可换行。
- AC-06（`建议采纳`）：通知收件箱继续使用顶栏打开的 Sheet，保持最近通知、未读提示、全部已读和选择通知操作；通知正文允许换行，0、1、很多通知均不破版。
- AC-07（`建议采纳`）：我的页面按确认表显示当前用户资料和现有编辑操作。当前用户为单一资料记录，不要求制造多条记录；验证可选字段为空及现有契约允许的长文本时页面不破版。
- AC-08（`用户要求`）：今日视图、审核队列、审核详情、门店、账号和通知收件箱在 768、1024、1440 宽度下均能承载超长文本及 0、1、很多条对应列表数据而不破版。审核详情分别覆盖检查项与聊天消息；表格自身的横向滚动不视为页面级横向滚动。Web 不覆盖 768 以下。
- AC-09（`用户要求`）：七页状态均以文字和语义色表达，不只依赖颜色。`apps/web/src` 不出现写死的颜色值，颜色只消费 `tokens.css` 的变量或现有语义类。
- AC-10（`用户要求`）：实现只写入 `apps/web` 页面呈现代码；共享 token、公共组件外观、导航、页面框架、业务逻辑、路由、数据获取和接口保持既有实现。
- AC-11（`用户要求`）：最终代码审查任务中运行并记录 `pnpm typecheck`、`pnpm lint`、`pnpm format:check`、`pnpm build`、`FW_SLOT=1 pnpm --filter @apps/api test` 和 Web 界面 e2e。Web e2e 使用 `FW_SLOT=3 pnpm exec playwright test --config=playwright.web.config.ts`。若选择器失效导致失败，改按角色或文案定位，保留所有用例。
- AC-12（`用户要求`）：方式 A 交接按页列出人工检查的宽度和数据情况，并提供七页 1440 改版前后对照；改版后的 768、1024、1440 页面截图保存在本单元 `evidence/after/`。

## 验收方式

`A 人工验收`

Agent 完成各页任务、机器门和最终代码审查。交接时按 AC-12 提供截图与逐页人工检查范围；用户确认后再完成 Promote 与归档。
