# 任务与条目状态机

> ID：`FW-028`
>
> 状态：`approved`

## 目标

接力线一第 5 个。系统每天按门店日程生成任务；本店任一店长在时间窗内逐条上传、覆盖；交齐自动已提交，截止未交齐为逾期；按判定时间锁分并给出整单结论。本单元由管理员人工判条目（AI 在线二接入），API 为主，Web 审核页同步改为逐条判。

## 非目标

- 不做 AI 审核、通知、看板指标（线二）。
- 不做 Mobile 店长端界面（FW-029）；本单元 Mobile 只保证不崩（旧入口隐藏）。
- 不做临时任务；店长不能新建巡检。

## 验收标准

时间相关的 AC 全部用注入时钟或改库取证，不等真实时间。

- AC-01（`用户要求`）：每日生成：按商家时区，每天为每家启用门店生成 `planFor` 的任务，幂等（重复执行不重复生成）；当天方案、选用或跳过日期改动后，当天还没开始（无任何上传）的任务按新方案增删改，已开始的不变。
- AC-02（`用户要求`）：任务状态：未开始、进行中、已提交、逾期；一个任务最多一张巡检单，有首次上传时在首传中创建，并发首传只建一张（唯一约束取证）；若全程未上传，系统在截止自动判定时补建无上传巡检记录，`inspectorId` 为空。
- AC-03（`用户要求`）：上传时间：窗口开始前 1 小时起才能上传；截止后，从未上传的条目拒绝（409）；被打回的条目到截止后 1 小时可以重传，之后拒绝。
- AC-04（`用户要求`）：本店任一店长可上传任一条目；每次上传含照片（不少于最少张数，只接受本次上传的照片）、自评、备注（张数为 0 时必填）；同一条目以最后一次为准、整条覆盖；截止前已通过的条目也可以覆盖，覆盖后回到待审。记录每条的提交人和服务端上传时间。别的门店店长 403。
- AC-05（`用户要求`）：所有条目都有上传后，任务自动变为已提交；截止时未交齐为逾期。
- AC-06（`用户要求`）：条目结论：通过、打回、不合格。本单元由 admin 逐条判；截止后 1 小时内可以打回，之后只能判通过或不合格。截止时未上传、截止后 1 小时仍是打回的条目，判定时记不合格并标「未完成」。
- AC-07（`用户要求`）：判定时间：截止时没有打回条目则截止时判定；有打回则等它们都有结论再判，最晚截止后 1 小时强制判定。判定时锁分：分数 = 通过条目数 ÷ 总条目数 × 100，四舍五入取整。整单不通过 = 任一严重项不合格，或不合格（含未完成）条目达到一半。结论绑定门店。
- AC-08（`用户要求`）：改判：判定后 admin 可以逐条改结论，分数与整单结论重算；每次改判记录操作人、时间、原结论、新结论。
- AC-09（`用户要求`）：自检准确率的数据可算：保存每条第一次上传的自评和第一次结论。
- AC-10（`用户要求`）：Web 审核页改为按任务、逐条判与改判，显示每条提交人昵称和"上传于 HH:mm"；总部可读巡检聊天但没有输入框或发送按钮，聊天 POST 返回 403。界面 e2e 覆盖：生成当天任务 → API 上传全部条目 → admin 打回一条 → 重传 → 判定后显示分数与结论 → 改判一条后分数变化。
- AC-11（`建议采纳`）：旧的整单提交、整单审核接口与"店员建单"删除，不保留备用代码；种子改为生成过去 7 天任务与判定结果。
