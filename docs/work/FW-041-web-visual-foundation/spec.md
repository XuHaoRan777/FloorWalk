# Web 控制台视觉基础（阶段一）

> ID：`FW-041`
>
> 状态：`approved`

## 目标

为企业日常巡检管理重做 Web 控制台的视觉基础。统一浅色样式 token、页面壳和公共状态，完成总部看板与模板编辑两张样板页；保留其它页面的业务行为，使其在目标宽度下可用且不破版。规格批准后才开始代码变更。

## 方向选择

用户于 `2026-11-19` 确认样板页为「总部看板」和「模板编辑」，并选定方向 `01 钴蓝运营台`。用户没有另行说明选择理由。

方案理由：紧凑的左侧分组导航、清晰的统计周期和层次分明的数据表，适合管理员在桌面上反复查看门店状态。钴蓝、青绿和告警色为操作与数据系列提供可辨的职责，轻量阴影和较小圆角给白色工作表面增加边界与高度。

方向参考卡和 1440px 渲染截图保存在本单元 `evidence/direction-cards/01.md` 与 `evidence/screenshots/`。实际落地取值以完成后的 `docs/context/design.md` 为准。

## 非目标

- 不改变业务逻辑、路由、数据获取、API 契约、权限、认证、数据用途和部署拓扑。
- 不按商家切换主题，不做深色模式或主题切换。继续使用 Radix、Tailwind 4 和 lucide 图标。
- 不改 Mobile 页面代码或其页面样式。本单元仅维护由 `packages/tokens/tokens.css` 生成的 `packages/tokens/native.json`，并验证 Mobile 类型检查、构建和现有界面 e2e。
- 不逐页重做样板页之外的 Web 视图。其它已注册路由和控制台分区只要求现有操作可用、内容不遮挡且页面不横向破版。
- 不新增依赖。动效使用 CSS 和浏览器 View Transitions API，并提供浏览器不支持时的即时切换回退。
- Web 浏览器视口不覆盖小于 `768px`。

## 验收标准

- AC-01（`用户要求`）：在 `1440px` 总部看板或模板编辑中，工作区可见背景、卡片和具有独立边界的浮层至少三层；主品牌色为钴蓝 `#365de8`，辅助色为青绿 `#058d84`，成功、警告、危险色有各自用途；面板使用 `7px` 圆角并能看到轻量阴影或边框。页面保持浅色且没有主题切换入口。
- AC-02（`用户要求`）：`packages/tokens/tokens.css` 按用途定义画布、卡片、浮层、描边、品牌、辅助、成功、警告、危险及必要前景/遮罩色；同时定义正文字号层级、间距、圆角、阴影、动效时长与缓动。Tailwind 主题和既有共享字体消费这些 token，不在页面间另造一套取值。
- AC-03（`用户要求`）：Radix 公共组件、侧栏和共用页面框架有默认、悬停、键盘聚焦、禁用和加载外观；公共加载、空内容和出错状态有一致可辨的结构和颜色语义。状态不只以颜色传达。
- AC-04（`用户要求`）：按下、面板展开/收起、页面切换、数据数字更新和列表项新增/删除都有可观察的中等动效；`prefers-reduced-motion` 下减少动态或即时切换。优先使用 CSS 和 View Transitions；若实现确需新依赖，修改 spec 并取得用户批准后才安装。
- AC-05（`用户要求`）：总部看板在 `768px`、`1024px` 和 `1440px` 宽度下保留本周/本月切换、完成率、逾期、自检准确率、平均分和门店/店长/日期三个互斥维度。在「门店」维度可以读取全部 12 家种子门店、应完成与已完成数、完成率、自检准确率、平均分和最近判定；表格列不需要横向滚动，`1440px` 下 12 行与其数值均在首屏可见。截图与交互核验不组合当前产品中互斥的不同统计维度。数据符合 Northbean 种子：本周应完成和交齐均为 11 项，逾期 0，自检准确率 97.7%，平均分 83.3；`NB-005` 本周 2 项平均 100 分，`NB-012` 本周 3 项平均 50 分且最近判定为不合格。
- AC-06（`用户要求`）：模板编辑在 `768px`、`1024px` 和 `1440px` 下可读取模板、编辑名称和 AI 设置、增加/移除检查项、调整顺序并保存。字段说明、焦点、禁用/保存中反馈以及验证和网络错误状态均可辨认；控件和文本不重叠、不溢出。行为继续使用既有 API 与保存语义。
- AC-07（`用户要求`）：动业务代码前在 `1440px` 为 `router.tsx` 中每条注册路由和控制台十个分区各保存一张当前页面截图到 `evidence/before/`。用同一数据、视口和默认状态记录两张样板页的前后对照。其它视图保持功能不变，刷新打开可到达，既有主要操作仍可用，页面无横向溢出、关键内容遮挡或控件叠压；检查宽度为 `768px`、`1024px`、`1440px`。路由与分区清单以本 spec 的「事实边界」为准。
- AC-08（`用户要求`）：所有应用色值只在变量文件 `packages/tokens/tokens.css` 中声明。`apps/web/src` 的 CSS、TSX 和 Tailwind 类不直接写十六进制、RGB/HSL、黑/白等颜色字面量；颜色通过主题变量或语义 token 消费。已存在的语义危险色和状态含义得到保留。
- AC-09（`用户要求`）：按维护命令重新生成 `packages/tokens/native.json` 且 `--check` 通过；Mobile `typecheck`、`build` 和界面 e2e 通过。Native 只消费自身现有 IBM Plex 字体注册映射，不改 Mobile 页面代码，不以 Expo Web 截图代替原生外观验收。
- AC-10（`用户要求`）：以下命令全部通过：`pnpm typecheck`、`pnpm lint`、`pnpm format:check`、`pnpm build`、`FW_SLOT=1 pnpm --filter @apps/api test`、`FW_SLOT=3 pnpm exec playwright test --config=playwright.web.config.ts`、`FW_SLOT=1 pnpm e2e:mobile`、`pnpm --filter @apps/mobile typecheck`、`pnpm --filter @apps/mobile build`、Native token 生成与检查。若 e2e 因选择器失效失败，改用角色或可见文案定位元素，保留所有现有用例。
- AC-11（`用户要求`）：实际设计取值、token 用途、常用组件/状态约定、动效和无障碍偏好写入 `docs/context/design.md`；该文件描述落地后的实际实现，不写未实现的计划值。

## 验收方式

`A 人工验收`

Agent 完成 AC-07 的改版前截图，再按任务记录逐步验证实现，执行 AC-10 全量机器门并做最终代码审查。交接时提供总部看板与模板编辑的前后对比和 `768px`、`1024px`、`1440px` 的截图路径，由用户查看成品。

## 事实边界

当前注册路由：`/` 登录、`/console` 控制台、`/register` 注册、`/forgot-password` 找回管理员密码、`/change-password` 强制修改密码、`/_design-samples` 历史样板，另有根级 404 fallback。

控制台同一侧栏页面壳内的十个分区：今日视图、审核队列、总部看板、门店、模板、AI 审核标准、日程方案、门店日程安排、账号、我的。审核详情与通知收件箱是控制台内视图/浮层，不是独立路由。两张样板页均保留既有业务默认值和互斥维度；趋势、排行与门店表不同时堆叠。
