# AI 逐条审核

> ID：`FW-030`
>
> 状态：`approved`

## 目标

接力线二第 1 个。店长上传任一条目后，AI 异步审核该条，给出通过、打回或属实不合格；失败自动重试，仍失败转管理员人工判；关闭 AI 的模板走纯人工流程。本单元用假模型取证，真模型在线尾 A 单元验收。

## 非目标

- 不接真模型、不调提示词（FW-038 做）。
- 不做管理员的审核界面（FW-031）、看板、改判（FW-031）。
- 不做通知（FW-036）。
- 不改任务与条目状态机的时间规则与判定时间；只填充"条目结论"的产生者。

## 验收标准

AI、权限与失败路径都由 API 测试取证。

- AC-01（`用户要求`）：先跑一次模型探针脚本，覆盖图片输入、结构化输出 JSON（含三种结论的 schema）、从本地存储或 OSS 签名链接下载图片；产物写进 `evidence/`（不入库），生成一份 Markdown 报告。报告不进 AC；明显不行时用户叫停本单元。
- AC-02（`用户要求`）：假模型按请求里的"预期结论"字段返回固定结果，供 e2e 用；配置键 `AI_REVIEW_DRIVER` 为 `fake` 或 `openai`，前者不发外部请求；`OPENAI_BASE_URL`、`OPENAI_API_KEY`、`OPENAI_MODEL` 登记属性注释，`fake` 时不必填。
- AC-03（`用户要求`）：条目上传后入队异步审核：队列按单条粒度，失败按指数退避最多重试 3 次（可注入时钟取证）；仍失败标为"待人工"，此时该条目需要管理员手工判。
- AC-04（`用户要求`）：AI 结论三种：通过、打回（附一条理由，1～500 字）、属实不合格（附理由）；打回不设次数上限（契合 FW-028）。覆盖同一条目的新上传会取消未开始的上一次调用。
- AC-05（`用户要求`）：关闭 AI 的模板：条目上传后不入队，直接置为"待人工"；FW-028 的时间规则不变。
- AC-06（`用户要求`）：自检准确率的数据可算：确保第一次上传的自评和第一次结论已被保存（接 FW-028 的字段）；新增一份只读接口 `GET /api/stats/self-check?scope=site|manager&id=...&from=...&to=...` 供看板用。
- AC-07（`建议采纳`）：权限：队列和"待人工"相关接口只给 admin；跨商家 404；服务端错误走统一 `{code,message}` 格式。
