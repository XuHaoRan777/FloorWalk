# AI 真模型验收与提示词调优

> ID：`FW-038`
>
> 状态：`approved`

## 目标

接力线二线尾。把 AI 审核从假模型切到真模型（OpenAI 兼容接口），用演示数据和真实样本照片走一遍，调审核提示词让判断稳定；同时顺带检查基线里标「AI 定」的条目，有不合适就在本单元或 testlog 里记录。

## 非目标

- 不改状态机、不改 API 语义（必要时发现问题通过回修或 testlog）。
- 不做模型供应商选型：按用户在 `.env` 配置的 `OPENAI_BASE_URL` 走。

## 特殊授权

- 2026-11-18：用户授权 Agent 向该地址发真实请求，本单元合计不超过 30 次调用；AC-01 与每轮 AC-04 均计入上限，超出后停止并报告，不自行增加额度。只检查 `.env` 中键是否存在，不读取、不打印其内容。

## 验收标准

- AC-01（`用户要求`）：切到真模型后，Agent 在本地跑 `AI_REVIEW_DRIVER=openai` 的烟雾测试。使用现有测试设施程序生成三张图：清晰的“冷柜温度 3°C”（期望通过）、清晰的“冷柜温度 12°C”（期望属实不合格或打回）、前一张 3°C 图片的高斯模糊版（期望打回）；验收要点为“温度在 0～5°C”。每张记录模型结论、理由、延迟及 token 数并写入本单元 `evidence/`，不新建临时目录。
- AC-02（`用户要求`）：不重建种子；使用 Northbean 种子管理员、绑定 NB-001 的店长、门店及现有 AI 标准，创建名称不与种子模板重复的新 AI 模板。模板至少包含严重项“冷柜温度”（验收要点“温度在 0～5°C”）和非严重项“陈列柜玻璃”（验收要点“玻璃干净可辨”）。新建一份简单日程并分配给门店，或以更短路径插入一条验收任务。店长依次上传清晰 3°C、清晰 12°C、模糊 3°C 到“冷柜温度”项，每次覆盖前一次，并另上传一张模糊图到“陈列柜玻璃”项；记录每次 AI 结论和理由。任务到期后观察自动分数与整单结论，管理员改判一项后复核分数变化及看板分数。完成后在 plan「交接」写两行：偏差（包括 AC-04 提示词调整与新建模板细节）和需用户测试的真实 Mobile 店长上传体验；单元登记为“待人工验收”，待用户确认后归档。
- AC-03（`用户要求`）：对基线里"AI 定"的 17 条顺带检查，异常写进 plan「决策与偏差」或开 testlog 行；没有异常就记一行"均符合预期"。
- AC-04（`用户要求`）：若需要补足证据可读性判断，在 `apps/api/src/ai` 的请求拼装层增加系统级通用证据评估准则，顺序为系统兜底段、管理员业务标准、检查项与验收要点；不修改 FW-026 的种子 AI 标准或种子模板。AC-02 按其流程可新建专用验收模板并绑定现有 AI 标准。复用 AC-01 的三张合成图验证：清晰 3°C 应为通过，清晰 12°C 应为属实不合格或打回，模糊 3°C 应为打回。每轮三次请求并记录输出；若模糊图仍通过，可调整兜底段再跑，最多三轮。所有调用计入本单元 30 次总上限，达到轮数或额度上限仍不符合预期即停止并报告，不自行增加额度。
