# Web 控制台剩余页面布局整理（二）

> ID：`FW-043`
>
> 状态：`approved`

## 目标

按 FW-041 确定的设计基线，重排 AI 审核标准、日程方案、门店日程安排、登录注册类页面和根级 404。
只整理 Web 页面布局，保留业务逻辑、路由、数据获取、接口和既有共享样式基础。
验收方式为 A。

## 非目标

- 不修改 `packages/tokens/tokens.css` 的 token、取值或语义映射。
- 不修改公共组件外观、控制台导航或既有页面框架。
- 不改变业务逻辑、路由、数据获取、API 契约、权限、认证语义、数据用途或部署拓扑。
- 不修改 `apps/web` 以外的业务代码，不修改 Mobile 页面，不新增依赖。
- Web 页面不覆盖 `768px` 以下视口。

## 验收标准

- AC-01（`用户要求`）：AI 审核标准按确认表组织标题、操作、标准名称和提示词编辑区。长标准名称可换行，提示词及错误、保存反馈各自在对应编辑区附近；0、1、很多条标准均不破版。
- AC-02（`用户要求`）：日程方案按确认表组织标题、操作、方案选择和七天排班编辑。长方案名可换行，启用天数与名称并列，时区及跨日说明紧邻排班区；0、1、很多条方案及任务均不破版。
- AC-03（`用户要求`）：门店日程安排按确认表组织标题、批量操作和门店表。门店编码、停用状态、选用方案与跳过区间均留在相应门店行；长门店名和备注可读，0、1、很多条门店及区间均不破版。表格自身横向滚动不视为页面级横向滚动。
- AC-04（`用户要求`）：登录、注册、找回管理员密码和强制改密共用现有单栏表单布局，并保留各页现有字段和操作。校验错误、网络错误和提交中三种状态均可辨；长文本不破版。
- AC-05（`用户要求`）：根级 404 保留现有独立外框，清楚显示页面不存在及返回首页操作；页面内容不因视口变窄而破版。
- AC-06（`用户要求`）：上述页面在 `768px`、`1024px`、`1440px` 宽度下均无页面级横向滚动。表格自身横向滚动不计入页面级横向滚动；Web 不覆盖 `768px` 以下。
- AC-07（`用户要求`）：`apps/web/src` 不出现写死的颜色值，颜色只经 `packages/tokens/tokens.css` 的变量或既有语义类表达。状态使用文字与语义色，不只依赖颜色。
- AC-08（`用户要求`）：仅整理 `apps/web` 页面布局；不修改共享 token、公共组件外观、控制台导航、既有页面框架、业务逻辑、路由、数据获取和接口。若 Web e2e 因选择器失效变红，按角色或可见文案更新选择器并保留用例。
- AC-09（`用户要求`）：最终代码审查任务运行并记录 `pnpm typecheck`、`pnpm lint`、`pnpm format:check`、`pnpm build`、`FW_SLOT=1 pnpm --filter @apps/api test` 和 Web 界面 e2e。Web e2e 使用 `FW_SLOT=3 pnpm exec playwright test --config=playwright.web.config.ts`。
- AC-10（`用户要求`）：方式 A 交接按页列出需要用户检查的宽度和数据情况，并提供目标页面 1440px 修改前后对照。修改后 768px、1024px、1440px 页面证据保存在本单元 `evidence/after/`。

## 验收方式

`A 人工验收`

Agent 按页面任务取证、运行机器门并完成最终代码审查。交接按页提供人工检查范围和 1440px 前后对照；由用户检查页面表现并确认后完成 Promote 与归档。
