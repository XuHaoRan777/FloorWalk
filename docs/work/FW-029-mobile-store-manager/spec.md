# Mobile 店长端

> ID：`FW-029`
>
> 状态：`approved`

## 目标

接力线一第 6 个，线尾。店长在 Mobile 看到本店今日任务，现场用相机逐条拍照上传、看结论、重传打回项；时间窗外按钮按规则禁用；记录页适配新状态与调店可见性。原生模拟器取证。

## 非目标

- 不做 Mobile 管理端、通知、个人中心（线二）。
- 不防翻拍屏幕、不加水印。
- 不改 API 语义（FW-028 已定）；只补 Mobile 需要的读接口字段时，不改已有字段含义。

## 验收标准

- AC-01（`用户要求`）：「今日任务」列出本店当天任务：模板名、时间窗、状态（未开始、进行中、已提交、逾期）；跨零点显示为"22:00～次日 00:30"。
- AC-02（`用户要求`）：任务详情逐条显示：验收要点、最少张数、当前结论（待审、通过、打回、不合格）、最后提交人昵称和"上传于 HH:mm"。
- AC-03（`用户要求`）：照片只能用相机拍：上传入口调起相机，不提供相册；张数不足时不能提交该条并提示还差几张；张数为 0 的条目只填备注。
- AC-04（`用户要求`）：时间限制在界面上体现：窗口开始前 1 小时之前显示"HH:mm 起可开始"；截止后未上传的条目不可操作；打回条目显示重传截止时间，到时不可操作。服务端拒绝时显示中文提示。
- AC-05（`用户要求`）：同店两位店长：一位上传后，另一位刷新能看到该条已上传和提交人；覆盖后显示最后提交人。
- AC-06（`用户要求`）：「记录」按任务显示历史，状态与分数按新状态机；调店后原门店只显示自己参与过的。
- AC-07（`建议采纳`）：聊天面板保留在任务详情，规则不变；聊天发图仍可以用相册。
- AC-08（`用户要求`）：原生模拟器取证：Android 模拟器走通"今日任务 → 拍照上传一条 → 看到待审 → （API 打回）→ 重传 → 已提交"；相机用模拟器虚拟场景。截图写进 `evidence/`（不入库）。
