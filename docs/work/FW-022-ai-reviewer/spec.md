# AI 审核适配器

> ID：`FW-022`
>
> 状态：`approved`

## 目标

并行组 g03 线 L3，只有一个单元（槽位 3）。在 FW-017 定的 AI 适配接口后面实现 OpenAI 兼容适配器：把审核标准提示词、模板和检查项、店员自评、照片拼成一次请求，拿回逐项结论并校验；出错时返回"转人工"。设 `AI_DRIVER=openai` 即可切换，默认仍是假适配器。

## 非目标

- 不接入提交流程，不加表，不做界面（功能组做）。
- 不调提示词质量、不判断 AI 判得准不准（Backlog 第 15 项，方式 A）。
- 不改 AI 接口、输入输出 schema、`ai/index.ts` 的驱动选择（FW-017 定）。
- 不做重试队列、并发限流、费用统计。

## 验收标准

- AC-01（`用户要求`）：`prompt.ts` 按输入拼请求：系统消息说明角色和输出格式；用户消息依次列出审核标准提示词、模板名、每个检查项（编号、标题、必拍、严重项、最少张数、验收要点、店员自评）和它的照片；每张照片标明属于哪一项。单元测试对固定输入快照比对。
- AC-02（`用户要求`）：照片传法按 FW-017 探针结果：签名链接能被模型拉取就传链接，否则读出字节转 base64 data URL；发送前长边压到不超过 1280 像素、JPEG 质量 80。单元测试用 `sharp` 现场生成一张 2000×1500 的 JPEG，验证压缩后长边 1280、比例不变；再生成一张 800×600 的验证不放大。（2026-11-03 用户原话"按建议"：种子照片是 1×1 占位图，测不出读图）
- AC-03（`用户要求`）：`openai.ts` 调 `OPENAI_BASE_URL` 的 chat completions，模型用 `OPENAI_MODEL`；按探针结果用 JSON schema 结构化输出，或在提示词里要求 JSON 再解析。返回结果按 FW-017 的输出 schema 校验；检查项编号必须和输入一一对应，多出、缺少都算不符。
- AC-04（`用户要求`）：转人工的情况各有一个测试（用可注入的假客户端）：HTTP 错误、超时（默认 60 秒，可配置）、返回不是合法 JSON、schema 不符、检查项对不上、整单结论与逐项结论矛盾（有严重项判不合格却给整单通过）。都返回 `{ kind: 'needs_human', reason }`，`reason` 是中文且不含密钥和完整请求体。
- AC-05（`用户要求`）：配置检查：`AI_DRIVER=openai` 而 `OPENAI_API_KEY` 或 `OPENAI_MODEL` 缺失时，API 启动失败并报出缺的键名，不打印值。
- AC-06（`用户要求`）：冒烟测试只在 `FW_AI_SMOKE=1` 时运行：用现场生成的 640×480 白底红色方块 JPEG 作为一个必拍项的照片，加一段简短的审核标准（"照片里应有红色方块"），调用一次真实模型，只断言返回通过 schema 校验（或明确返回 `needs_human` 并记录原因），不断言判得对不对。（2026-11-03 用户原话"按建议"：种子照片是 1×1 占位图，测不出读图）原始响应的摘要（结论、每项理由前 50 字、耗时、token 用量）写进证据。

## FW-017 探针结论（2026-11-03）

- 读图：通过。`sharp` 生成 640×480 白底红色正方形 JPEG（3653 字节），base64 发送；模型描述“图像背景为浅灰白色（接近白色），画面中央有一个纯红色的正方形色块，四边平直、边与画面边缘平行，内部为均匀实心红色，无文字、纹理或其他可辨识物体。”。耗时 7076ms，token 用量：输入 443、输出 160、合计 603（image 302）。旧 1×1 图返回的 502 是先前配置问题，不作为视觉能力结论。
- JSON schema 结构化输出：通过。请求使用 `response_format.type=json_schema`，响应合法且符合探针 schema；L3 按此实现，再用共享 AI 输出 schema 校验。
- 本地签名链接：不通过。本地读取 200；模型端 HTTP 400 `invalid_parameter_error`：`The provided URL does not appear to be valid. Ensure it is correctly formatted.`（313ms）。此前网关也曾拒绝端口 3110；L3 读字节转 base64。OSS 公网签名 URL 在 FW-023 AC-04 单独验证。
- 配置地址兼容：探针会剥掉 `OPENAI_BASE_URL` 末尾的 `/chat/completions`，避免 SDK 重复追加路径。原始错误为 HTTP 404 `Invalid URL (POST /v1/chat/completions/chat/completions)`；未修改环境文件。
- 探针脚本为 `scripts/ai-probe.mjs`；仅输出配置键存在性及脱敏响应，不保存密钥或签名 URL；临时生成图通过存储接口写入并在 finally 删除，无数据库访问。
