# 多商家隔离与门店范围

> ID：`FW-018`
>
> 状态：`approved`

## 目标

并行组 g03 线 L1 第 1 个（槽位 1，[`howto/parallel.md`](../../howto/parallel.md) 第 3、4 节）。每个用户只能看到、操作自己商家的数据；主管只能看到和审核自己名下门店的单。界面不新增功能，只是看到的范围变窄。

## 非目标

- 不做商家注册、门店指派主管、账号管理（FW-019、FW-020）。
- 不改契约、`schema.ts`、迁移、`auth.ts`；门店范围用 FW-017 写好的函数。契约不够用就停下，按 parallel.md 第 5 节。
- 不改界面样式。

## 验收标准

API 测试和界面 e2e 用 FW-017 种子里的两个商家（Northbean、演示二号）和两个 Northbean 主管。

- AC-01（`用户要求`）：现有全部业务接口按商家隔离：用演示二号的 admin、主管、店员分别请求 Northbean 的巡检单、照片签名、聊天、门店、模板、看板，单个资源返回 404 `NOT_FOUND`，列表里不出现。API 测试按路由表遍历，每条至少一个跨商家用例。
- AC-02（`用户要求`）：主管范围：Northbean 主管甲的审核队列、看板、门店列表只有自己名下的 6 家；打开或审核主管乙名下门店的单返回 403 `FORBIDDEN`。
- AC-03（`用户要求`）：admin 看本商家全部门店，可以审核任何门店的单；没指派主管的门店只有 admin 能审，主管审它返回 403。
- AC-04（`用户要求`）：店员范围不变（本店），但跨商家时同样是 404。
- AC-05（`用户要求`）：模板与门店管理：admin 和主管读到的是本商家的；新建门店、模板落在操作者的商家；门店编码和模板名只在本商家内查重（两个商家可以各有 `NB-001`）。
- AC-06（`用户要求`）：Web 界面 e2e：主管甲登录后队列和看板只显示 6 家店；admin 登录看到 12 家。现有 Web、Mobile、演示链 e2e 全绿，断言为新范围调整可以，不放宽。
