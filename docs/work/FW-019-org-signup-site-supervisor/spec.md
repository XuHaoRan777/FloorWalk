# 商家注册与门店指派主管

> ID：`FW-019`
>
> 状态：`approved`

## 目标

并行组 g03 线 L1 第 2 个（槽位 1）。任何人可以在 Web 首页注册一个新商家，成为它的商家管理员并直接进入控制台；商家管理员可以给门店指派或取消主管。

## 非目标

- 不做建账号、改密码、停用（FW-020）；新商家注册后只有一个 admin，没有主管可指派时界面显示"暂无主管"。
- 没有验证码、邮件验证、额度限制（产品基线：暂不考虑上线）。
- 不改契约、`schema.ts`、迁移、`auth.ts`。
- 不改界面样式，用 FW-016 的组件。

## 验收标准

- AC-01（`用户要求`）：`POST /api/orgs` 建商家和 admin，返回 201 并设置会话 cookie；时区默认 `Asia/Shanghai`；新商家没有门店、模板。API 测试覆盖失败路径：邮箱已存在（任何商家）409 `INVALID_STATE`；密码少于 8 位、商家名为空、邮箱格式不对 400 `VALIDATION_FAILED`；已登录状态下注册也建新商家，不影响原会话以外的数据。
- AC-02（`用户要求`）：Web 首页有"注册商家"入口，注册页填商家名、管理员姓名、邮箱、密码，成功后进入控制台，看板为空状态；错误显示中文提示。
- AC-03（`用户要求`）：`PUT /api/admin/sites/:id/supervisor` 只有 admin 能调：指派本商家的主管成功；指派另一商家的用户或非主管角色 400 `VALIDATION_FAILED`；主管调用 403；另一商家的门店 404；`userId: null` 取消指派。一店最多一个主管，重新指派即替换。
- AC-04（`用户要求`）：`GET /api/admin/sites` 每家店带当前主管；Web 门店页显示主管列，admin 可以从本商家主管里选择或取消；主管登录看不到指派控件。
- AC-05（`用户要求`）：指派后范围立即生效：把一家店从主管甲改给主管乙，甲的队列里不再有这家店，乙的有。界面 e2e 覆盖。
