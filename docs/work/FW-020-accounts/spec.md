# 账号体系与会话续期

> ID：`FW-020`
>
> 状态：`approved`

## 目标

并行组 g03 线 L1 第 3 个，线尾（槽位 1）。商家管理员和主管在 Web「账号」页建员工账号、重置密码、停用；员工首次登录必须改密码；会话改为闲置 7 天才失效。API 恢复按来源白名单的跨域与写请求来源校验。

## 非目标

- 不做个人中心（姓名、头像），只做改密码。
- 不做删除账号，只做停用；不做找回密码（没有邮件和短信）。
- 不改契约、`schema.ts`、迁移；`auth.ts` 在写入范围内。
- Mobile 只做"首次登录改密码"一屏，不做 Mobile 的账号管理。

## 验收标准

账号、密码、会话、跨域都属于认证与权限，失败路径全部由 API 测试取证。

- AC-01（`用户要求`）：`POST /api/admin/users`：admin 可以建 admin、主管、店员（店员必须带本商家的 `siteId`）；主管只能建店员且 `siteId` 在自己名下。失败路径：主管建主管或 admin 403；主管给不在名下的门店建店员 403；`siteId` 属于另一商家 404；邮箱已存在 409；密码少于 8 位 400。新账号 `must_change_password` 为真。
- AC-02（`用户要求`）：`GET /api/admin/users`：admin 看本商家全部账号；主管只看自己门店的店员，看不到其他主管和 admin。
- AC-03（`用户要求`）：停用 `PATCH /api/admin/users/:id { disabled: true }`：立即吊销该账号全部会话，它的下一个请求 401；停用后登录 401；重新启用后可以登录。失败路径：主管停用主管或 admin 403；停用最后一个启用的 admin 409；跨商家 404。停用的账号在巡检单、聊天里的名字照常显示。
- AC-04（`用户要求`）：上级重置 `POST /api/admin/users/:id/password`：设新初始密码，吊销该账号全部会话，`must_change_password` 置真；权限同停用。
- AC-05（`用户要求`）：首次登录改密码：`must_change_password` 为真时，除 `GET /me`、`POST /me/password`、`DELETE /auth/session` 外的受保护接口 403；`POST /me/password` 当前密码错 401、新密码少于 8 位 400、新旧相同 400；成功后清标记，吊销本人其他会话，当前会话保留。Web 登录后跳改密码页；Mobile 登录后跳改密码屏；改完进入原来的首页。
- AC-06（`用户要求`）：会话续期：有效 = 未吊销且最后活跃在 7 天内；每个受保护请求更新最后活跃时间；闲置超过 7 天的会话 401。测试用改库里 `last_seen_at` 的方式取证，不等真实时间。
- AC-07（`用户要求`）：跨域与来源：CORS 只回显白名单里的 Origin 并允许凭据；白名单从 `CORS_ORIGINS` 读，开发模式自动加上本机局域网 IP 的 Web、Expo 端口。带 Origin 的写请求，Origin 不在白名单 403；不带 Origin 的请求（原生 App、服务端）不受影响。API 测试覆盖：白名单内 GET 带凭据成功、白名单外的 GET 没有 CORS 头、白名单外的写请求 403、不带 Origin 的写请求成功。`e2e:cors` 按新规则改断言。写 `docs/adr/0003` 取代 0002，0002 状态改 `superseded`。
- AC-08（`用户要求`）：Web「账号」页：列表（姓名、邮箱、角色、门店、状态）、新建、重置密码、停用与启用；主管只看到自己门店的店员、只能建店员。界面 e2e 覆盖 admin 建一个店员 → 该店员登录被要求改密码 → 改完看到首页。
