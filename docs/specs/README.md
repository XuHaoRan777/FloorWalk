# 当前事实

本目录是项目唯一的"现在是什么"。每份文档写代码能观察到的行为、契约和缺口，不写目标或计划。**代码和这里不一致时，代码是事实，修这里。**

当前已有可运行工程骨架，尚无业务功能。产品意图见 [`../context/product.md`](../context/product.md)；上线缺口见 [`../backlog.md`](../backlog.md)。

## 两层内容，两种维护方式

| 层 | 写什么 | 维护 |
| --- | --- | --- |
| 行为与不变量（权威） | 状态机、守恒关系、权限规则、幂等语义、用户能做什么、故意没做什么 | 工作单元归档或修正模式收尾时改对应小节，修订记录加一行 |
| 结构事实（可再生） | 「数据契约」节的表和字段、文件顶部的代码路径、端点清单 | 归档时按 schema、控制器和目录树重新核对生成；读者以代码为准，这里只是索引 |

结构事实是漂移最快的一层，所以「数据契约」节标题带 `（归档时再生成）`，提醒读者它是快照，也提醒收尾时必须重新对账。

## 单份文档的结构

```markdown
# <功能名>

代码（归档时再生成）：<模块路径>

## <行为小节，按需多节>
## 没有的
## 数据契约（归档时再生成）
## 修订记录
```

不保留已删除端点、已删除表的描述——那是历史，在 `git log`。修订记录只记用户或调用方可观察的业务行为变化，一行一条，是历史变更的唯一位置；代码重构、字段重命名、文档重建不进修订记录。

工作单元 `spec.md` 的「涉及的当前事实」列出会改动的文档和小节；实现并验证后先改这里，再归档单元。功能细节只住在这里，工作单元文档只链接。

修正模式收尾时，以 [`../testlog.md`](../testlog.md) 为 Promote 输入，规则见 [`AGENTS.md`](../../AGENTS.md) 第 3 节。当前事实文档不链接工作单元快照，无论其是否归档。
