# 并行组试行记录

做法见 [`howto/parallel.md`](howto/parallel.md)。本页只追加，不改旧段：每组集成单元归档时追加一段，试行中遇到的坑随时追加。抽进模板时，本页就是 workflow 准入规则要的项目内失败记录，所以试行期的坑记这里，不进 [`pitfalls.md`](pitfalls.md)。

## 抽进模板的标准

2026-10-26 用户采纳。四条同时满足才抽：

1. 最近一组按下面「值不值」判为值。
2. 最近一组没有再新增开组门或并行规则（只改措辞不算）。
3. 另一个项目有具体的并行需求。
4. 只抽有本页记录可引、和技术栈无关的部分：角色、准入、tag 标记、写入范围、开组门、Backlog 冲突解法、独立审查。槽位端口、Expo、pnpm 留在项目的 dev-environment。形式是一份 howto 加内核一行触发，不往内核加规则。

判为停用时，把"试过、停用、原因"写进模板的说明，同样算抽。

## 值不值

目标是编码并行，后面一组比一组多开（用户 2026-10-26）。墙钟时间含人不在的时候，不当判据。开组前写好，收组时按它判：

- 值：集成阶段归到某个并行单元的回修不超过 1 个；人工触点按单元平均不多于串行基线。
- 停用：连续两组集成阶段的单元级回修都在 2 个以上；或人工触点按单元平均多于串行基线。
- 串行基线：两组之间的串行单元按同样口径计人工触点，记在下表「串行基线」行。

## 坑

一条一段，标题写组和日期。三行：现象（看到了什么）/ 原因（已确认的，猜测标"未确认"）/ 改了什么（改了哪份文件哪一节，没改写"没改，原因"）。

### g01 · 2026-10-24 · 契约单元机器门全绿，实测仍偏离契约

- 现象：FW-002 归档后核验，typecheck、API 测试、三槽位都通过，但 `GET /api/me` 返回 404（缺 `/api` 前缀）；演示链 e2e 只登录后对写死的 id 调一次提交，新库上返回 404；种子 20 张单 `created_at` 相同，`reviews`、`evidence` 都是 0 行；改检查项、审核两个接口拿请求 schema 校验响应；404 和 400 不是统一错误格式；API 没有 CORS。
- 原因：测试和实现同一个上下文写，e2e 用不带前缀的路径、拿请求 schema 当响应 schema，彼此一致却都没对照 spec；最终审查修复时给提交接口加了归属检查，演示链证据没有重取（AGENTS.md 第 7 节）。spec 也有缺口：AC-01 没写路由表与权限表，契约没定 404/400 错误码和"最近一次"按哪个时间。
- 改了什么：开修订单元 FW-003，契约加路由表，e2e 从路由表遍历，演示链写成完整链路；`howto/parallel.md` 第 1 节允许多个契约单元，第 6 节 T01 的检查范围扩到 schema 文件、迁移、`package.json` 和锁文件。

### g01 · 2026-10-24 · 种子分数与检查项不符，规格要求本身做不到

- 现象：FW-003 归档后核验，种子 78 张单里有 76 张的分数与它自己的检查项对不上（如 7/8 合格却记 62 分）；种子量 78 张，原意约 20 张。
- 原因：spec 写"其他店的分数各不相同"，8 个检查项只能算出 9 种分数，Agent 为满足这条凑出 53～63 的连号，破坏了"分数 = 合格项数 ÷ 总项数"；"再放 2～3 张"有歧义，且与"每家店恰好一张已判定的单"矛盾。两条都是起草 spec 时的错。
- 改了什么：修正模式 `8731c48`、`467f359`；本条作为起草契约 spec 的教训：数量和取值类要求先确认可满足，写"合计"或"每店"。

### g01 · 2026-10-24 · Agent 自行改了已批准的 spec

- 现象：FW-003 最终审查时 Agent 发现种子要求自相矛盾，按自己的理解改写了已批准 spec 的「种子重做」，在 plan 里记为"最终审查澄清"，没有停下问用户。

- 改了什么：内核第 7 节停止条件加「已批准 spec 有矛盾或要改」（只在 FloorWalk，模板未改）。并行单元无人值守，自行改 spec 的代价要到集成才暴露。

### g01 · 2026-10-24 · 新工作树 format:check 报 58 个文件

- 改了什么：`.gitattributes` 加 `* text=auto eol=lf`；两个种子文件做格式化；`howto/parallel.md` 第 1 节加一条：打 start 前在 master 上跑一次全量门禁。

### g01 · 2026-10-25 · Mobile 的 B 验收测不到原生上传，真机排查拖了 1.5 小时

- 现象：FW-005 的 6 项 Expo Web e2e 都通过了，但 Android 真机选照片上传失败，先后暴露两个 bug：一是用 `typeof window` 区分平台，原生端也有 `window`，结果走错了分支（`b468575`）；二是 Expo 57 的 `expo/fetch` 不接受 `{uri, name, type}` 写法，报 `Unsupported FormDataPart implementation`（`1bbb09c`）。从用户报告到修好约 1.5 小时。

- 改了什么：错误区分登记在 Backlog 第二组；Expo 57 上传写法升进 `pitfalls.md`；建议装 Android 模拟器，让 Agent 自己跑原生端和读 logcat（用户已经在问怎么装）。
