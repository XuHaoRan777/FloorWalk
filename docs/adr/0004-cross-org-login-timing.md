# 0004. 跨商家同名登录的候选数耗时边界

- 状态：`accepted`
- 日期：`2026-11-11`
- 来源工作单元：`FW-024`
- 取代：`-`

## 背景

允许多个商家使用相同登录名。登录时若登录名与密码匹配多个商家的启用账号，API 返回商家列表，客户端再提交所选商家建立会话。验证耗时会随该登录名命中的账号数变化；不存在的登录名则执行虚拟密码哈希。

## 决策

保留跨商家同名账号与登录时的商家选择流程，不对候选数量做额外的耗时填充。用户接受该简历项目中的剩余时序侧信道。

## 后果

候选列表只在密码匹配多个商家账号时返回，但请求处理时间仍可能暴露登录名对应账号的数量。该取舍不适用于未经重新审查的生产认证系统。

## 被否决的方案及原因

- 要求全局唯一登录名：与允许同名账号跨商家并由用户选择商家的已批准行为冲突。
