# 单元收尾与归档

触发：工作单元到 `verified` 或 `descoped`（[`AGENTS.md`](../../AGENTS.md) 第 11 节）。按顺序做，一个提交完成。全量机器门最费时，它的记录只认代码、不认文档，所以第 2 步之后起在后台，和第 3–8 步的文档工作同时进行，不排在最后干等。

1. 对账：列出本单元的代码提交（归属由钩子在提交时检查，这里不再逐个问归谁）：

   ```bash
   git log --format="%h %s" --grep "<单元号>" -- . ":(exclude)docs" ":(exclude)*.md"
   ```

   交付之后（方式 A 写完「交接」、方式 B 审查通过）的每个提交在「回修」里有一行，对不上的补上。「回修」里状态是 `延后` 的，每条在 Backlog「待开单元」有一行或已转进别的单元（校验器 `rework`）；没有用户同意的延后不能归档，回去做完或问用户。
2. 回修补审：其中带 `硬线：` 行的回修提交（`git log --all-match --grep "<单元号>" --grep "^硬线"`），没有补审证据行的，按 [`final-review.md`](final-review.md) 补审这几个提交，修完再往下。

   起门禁：从这里到归档提交不再改代码。先用起停脚本 `stop` 开发期起的服务（第 8 步的停服务提前到这里，门禁里的 E2E 可能要用同样的端口），再 `python scripts/gate.py --status` 看当前代码上各门的记录。有缺的（审查之后代码又改过，或跑完之后改过内容），把 `python scripts/gate.py` 全量起在后台：起了就接着做第 3 步，不等它、不轮询，第 9 步再看结果。它跑着的时候只改 `docs/` 和 `*.md`（指纹不含它们，记录不失效），不另起 `gate.py`；非改代码不可的，等它跑完，改完再全量起一次。
3. 交接：方式 A 用户已确认的，人工那行证据改 `passed`，用户原话写进备注。
4. Promote：按 `spec.md`「涉及的当前事实」改 `docs/specs/` 对应小节，每份加一行修订记录；回修改到的行为一并写进去；「数据契约」和代码路径按当前 schema 与目录树重新生成。`descoped` 不 Promote，未完成项留在 `plan.md`。
5. 复核下游：文档校验加 `--downstream <单元号>`，列出依赖本单元的活动单元和它们要消费的路径。逐个拿本单元实际交付（差异、刚 Promote 的 specs）对照下游 `spec.md`：「依赖」列的路径还在不在，AC 假设的接口、字段、可见性和失败语义变没变。变了的在下游 `plan.md`「决策与偏差」写一行：哪里变了、影响哪几条 AC；要改已批准 spec 的停下问用户（内核第 7 节）。没有下游的跳过；接力线在开下游前已经复核过线内的，这里只看线外的。
6. 升迁：`plan.md`「决策与偏差」里会影响后续的决策升入 `docs/adr/` 或 `specs/`；坑应在发现时已写进 `docs/pitfalls.md`（内核第 7 节），这里只复核：plan 里记了、pitfalls 里没有的补上，已写的按最终结论改准，证实不了的删掉；目录里若有长期有用的内容（设计规范、环境说明），搬到 `docs/context/` 或 `docs/howto/`。归档后的目录不被 `specs/`、`context/`、`adr/`、`pitfalls.md` 链接（校验器 `work-link`）。
7. 状态：`plan.md` 归档状态改 `archived`；文档校验加 `--sync-backlog` 更新「当前工作」表，从「待人工验收」删掉本单元的行，「已归档」加一行。
8. 清理：删除本单元 `evidence/`（不入库，删了只清本地）。用起停脚本 `stop` 开发期起的服务（归档时第 2 步已停，这里只确认），确认 `status` 为空、`dev-environment.md` 列的开发端口都没有监听（脚本外起的进程只有端口查得到）；后台门禁还在跑的，端口等它跑完再查，它自己起的服务这时还占着端口。端口被非登记进程占着的报给用户，不杀；用户要留的，写进提交信息：保留什么、哪个端口、为什么。
9. 门禁：等第 2 步起的那次跑完再看结果，没起的再 `--status` 核对一遍；记录按代码内容认，跑过之后原样提交的不用重跑。红门不在这里放行：修（改了代码就再全量跑一次），或停下问用户要不要在 `workflow.conf` 登记 `gate-known-red`。然后运行文档校验，0 个问题后提交；提交后文档校验加 `--archive-gate` 再跑一次（`gate.py` 没有这个参数），必须 0 个问题（它要求 `git status --short` 为空，登记的机器门在当前代码上都有通过记录；只改文档的归档提交不让记录失效）。工作树里有与本单元无关的未提交改动时，停下告诉用户，不替用户处理。

归档后的目录是历史：只读，新会话只在当前单元「依赖」列出或用户点名时读它。归档后的反馈进修正模式。
