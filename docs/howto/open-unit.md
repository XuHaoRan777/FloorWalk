# 开单元

触发：讨论新能力并要写 `spec.md`、`plan.md`，或用户要批准已经写好的单元（[`AGENTS.md`](../../AGENTS.md) 第 5、6 节）。这是编排会话：只写文档，不写代码，执行在新会话。并行组的开组和提示词见 [`parallel.md`](parallel.md)，不走第 6 步。

1. 讨论：按内核第 5 节。建议分两栏呈现：

   ```text
   你要求的（进入 spec.md）：<逐条复述>
   我建议补充的（默认不做，逐条采纳）：<建议> — 不加会怎样：<具体后果；"更严谨""便于扩展"不算后果>
   ```

2. 写文档：编号取现有最大号加一，从 [`docs/work/_template/`](../work/_template/) 建 `spec.md`、`plan.md`，状态都是 `draft`；文档校验加 `--sync-backlog` 重新生成 Backlog「当前工作」表，「待开单元」删掉对应的行。一串单元够接力门槛的，按 [`relay.md`](relay.md) 排线并做「批准时的环境确认」。
3. 查 AC 冲突：派一个没参与讨论的 Subagent，只读这份 `spec.md`（接力线读全线的 spec），找两类问题：同一前提下要求相反结果的 AC（如一条"撤销后所有请求返回 401"、另一条"重复调用返回成功"）；下游 AC 假设了上游 AC 没写的行为。它只报不改，查到的连同第 4 步一起摆给用户定。
4. 摆给用户审。在对话里写出来，不让用户去翻文件：
   - 两栏的结果：哪几条 AC 是 `用户要求`，哪几条是 `建议采纳`。
   - spec「结构与契约」一节的内容：本单元新增或改动的表、列、枚举值、对外接口及字段、配置键。没有就说"无"。
   - 验收方式；方式 A 预计要用户测什么；预计改动的 `docs/specs/` 小节。
   - 第 3 步查到的冲突，各自怎么改。
5. 记批准：用户在本会话明确说批准之后（沉默和"你看着办"不算），`spec.md` 状态改 `approved`，「批准记录」写用户原话和当天日期；`plan.md` 工作单元状态改 `approved`，再跑一次 `--sync-backlog`。然后提交，信息带单元号（只改文档的提交钩子不查归属，但归档时按单元号找提交）。用户要改的，改完只重摆改动的部分。
6. 给开工提示词：文档校验命令（内核第 14 节）加 `--kickoff <单元号>` 跑一次，接力线按顺序写全部单元号。报问题就修到通过；通过后把它输出的提示词原样放进代码块，贴在对话里，然后结束本会话。不改写提示词，不往里加规则或讨论内容：执行会话要知道的事只能写在 `spec.md`、`plan.md` 里，接力线上只有第一个会话看得到提示词。

用户说就在本会话做时，跑同一条命令确认就绪后直接开始，不必贴提示词。
