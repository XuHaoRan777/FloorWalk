# 最终代码审查

触发：派最终代码审查（[`AGENTS.md`](../../AGENTS.md) 第 9 节）、单元回修里带 `硬线：` 行的提交补审（第 10 节）、修正模式"收一下"时合审 `待审查` 行（[`fix-promote.md`](fix-promote.md)）。派发提示里写明本文件路径；审查者读本文件、`spec.md`、`plan.md` 和完整差异，不读实现者的推理。

## 七个失败域

逐项走完，每行写结论或不适用理由：

| 失败域 | 必查 |
| --- | --- |
| 认证与授权投影 | 服务端实时判定、投影与实际权限一致、未知绑定 fail-closed |
| 越权与混淆代理 | 调用方身份与资源归属、代理调用是否携带原始主体、敏感导出与审计 |
| 并发与幂等 | 竞态与 TOCTOU、锁顺序、重复提交、重放 |
| 数据解码与序列化 | 原生 SQL 返回类型、时间与数值解码、分页边界 |
| 迁移与回滚 | 前向迁移可重放、迁移历史未被破坏（含删除或改写已有迁移文件）、回滚边界 |
| 敏感数据与日志 | 凭据/Token 未落盘、日志与报错脱敏、artifact 不含敏感值 |
| 范围与结构膨胀 | schema、迁移、DTO、共享类型逐项对照 AC；指不出 AC 的字段、无调用方的枚举值和配置项 |

另查一项：第 14 节要求的认证、支付、权限、外部回调失败路径，证据行是不是测试命令；只有类型检查或构建的，算"有 AC 却无证据覆盖"。

## finding 规则

- 只报改变运行时行为、权限、数据正确性、失败模式或回滚可行性的问题，以及有 AC 却无证据覆盖的路径。
- 命名、格式、等价重写合并为一条；上限 5 项。
- 无法判定的写成待验证假设，不算 finding。
- 每条 finding 指明归哪个任务修；修完只复核那几条 finding，不重跑整轮审查。
- 审查只跑一次。补审和合审各是一轮，同样只跑一次，范围只限那几个提交或那几行。
