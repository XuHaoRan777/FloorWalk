# FloorWalk 已知陷阱

只记录已经由代码、测试或实际故障确认且仍可能影响后续工作的经验，每条可核对。动手前按触发条件 grep 本页（[`AGENTS.md`](../AGENTS.md) 第 1 节），不通读；工作单元收尾时把最终审查发现的可复现陷阱追加到此处（第 11 节）。

改工作流规则的准入也是本页：没有对应失败条目的机制不加。

## 检索方式

按 `触发场景` 分组，不按时间排列——让"我正要做 X"能在读全文之前定位到相关条目。组名取自项目实际动作类型（构建与产物、依赖与包管理、认证与会话、数据库与迁移、渲染与样式……）；一组超过 8 条再分，只有一条时放 `其他`。一条陷阱属于多个场景时放最可能被查到的那组，另一组留一行链接。

## 记录格式

```markdown
### <短标题>

- 触发条件：什么动作或组合会碰到；写具体版本号
- 现象：可观察到的错误信息或行为
- 根因：已确认的机制，不是猜测
- 规避方式：已验证的做法，以及明确禁止的做法
- 验证方式：怎么确认已规避
- 失效条件：什么变化会让本条不再适用
- 首次记录：`FW-NNN`
```

`触发条件` 决定能不能被检索到，写不具体等于没记录。`失效条件` 决定什么时候该标过时——没有它，本页会随依赖升级慢慢变成误导。条目过时后标注失效原因并保留，不删除。
